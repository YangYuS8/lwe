# 近期开发路线图

本页记录 LWE 后续工作的维护中方向。它不是长期归档文档：当产品范围、已验证运行时支持或发布优先级变化时，应同步更新。

## 指导原则

先稳定当前视频壁纸路径，再扩展运行时范围。LWE 应先把一条可靠工作流做好：发现 Wallpaper Engine 内容、理解兼容性、导入本地库、在已验证桌面目标上应用受支持的视频壁纸、重启后恢复，并可预期地清除。

在真实机器上实现并验证之前，不要把场景、网页或广泛桌面环境运行时行为写成已支持。

## 现在

### 对齐支持矩阵

兼容性是核心产品承诺。文档、共享策略、本地库/创意工坊徽标和桌面应用检查中的支持规则应保持一致。

当前权威运行时立场：

| 壁纸类型 | 当前方向 |
| --- | --- |
| 视频 | 已验证环境中的首发主要运行时目标。 |
| 场景 | 可识别元数据并用于兼容性报告；除非真实支持已实现并验证，否则不是首发运行时目标。 |
| 网页 | 可用于报告；不是首发运行时目标。 |
| 其他/应用 | 不支持用于 LWE 运行时工作流。 |

近期工作应消除代码或界面中暗示场景支持强于实际运行时能力的歧义。

### 稳定 `niri` 上的视频运行时

已验证桌面目标仍是 Wayland + `niri`。运行时工作应聚焦：

1. 将一个视频壁纸应用到一个显示器；
2. 在多个显示器上应用壁纸；
3. 清除一个显示器时不停止其他输出；
4. 应用重启后恢复已保存分配；
5. 在 Desktop 中展示可操作的恢复/运行时失败信息；
6. 保留贡献指南中记录的可选真实桌面验收流程。

### 让本地库应用行为明确

本地库是日常使用中心。它应清楚地区分当前可运行项目和仅可识别或降级项目。

有价值的后续工作：

- 对不可运行项目禁用或解释应用操作；
- 在应用控件附近展示运行时前提条件；
- 让过期 Desktop 状态可操作，而不仅是提示信息；
- 在可靠数据存在时填充当前显示器详情，例如封面图。

## 下一步

### 改进创意工坊获取和同步提示

Workshop 仍是发现和获取编排，而不是 Steam 下载的替代品。改进以下用户闭环：

- 打开 Steam 来源页；
- 通过 Steam 订阅或获取内容；
- 等待本地 Steam 同步；
- 解释缺失 `project.json`、缺失主资源和不支持类型。

### 为用户反馈增加诊断信息

在扩展到更多桌面环境之前，增加用户可复制到 issue 的诊断界面。它应优先展示可观察事实而不是猜测，例如包类型/版本、会话/合成器线索、显示器发现结果、运行时后端初始化结果、已知 EGL/mpv 可用性、Steam 集成状态和本地库内容数量。

### 加强发布冒烟验证

CI 已覆盖前端、文档、Rust 检查和包构建。可以增加轻量发布信心：

- 检查包产物名称；
- 在可行时检查 AppImage 可执行位或启动冒烟；
- 对影响运行时的发布记录手动验收说明；
- 除非存在已验证 runner，否则不要让真实桌面测试成为 CI 必需项。

## 以后

### 仅在验证后扩展桌面环境支持

不要把 `niri` 成功直接表述为通用 Wayland 支持。扩展应基于能力，并一次验证一个合成器。

可能顺序：

1. 强化 `niri`；
2. 在显示器身份和 layer-shell 行为验证后，尝试 `sway` 等 wlroots 风格目标；
3. 明确测试后再考虑 Hyprland；
4. GNOME/KDE 需要单独集成评估后再考虑。

每个新目标都需要真实桌面验证后才能在文档中宣称支持。

### 暂缓大型运行时范围扩展

除非已有聚焦设计和已验证实现，否则近期路线图不应包含：

- 完整场景壁纸运行时；
- 网页壁纸同等兼容；
- 创作者工具；
- 云或社区系统；
- 高级自动化规则；
- 守护进程优先架构。

## 维护提醒

- 保持用户可见行为与文档支持范围一致。
- 保持英文和简体中文文档同步。
- 涉及兼容性、导入路径、运行时行为和持久化状态的变化都应视为需要测试。
- 过时规划说明的有用内容合并进维护文档后，应删除原说明。
